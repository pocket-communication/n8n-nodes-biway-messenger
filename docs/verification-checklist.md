## Publication

`.github/workflows/publish.yml` is the workflow generated by `@n8n/node-cli`, kept unchanged:

- runs on a pushed tag matching `*.*.*` (for example `0.1.0`);
- `permissions: id-token: write` (provenance) and `contents: read`;
- `npm ci`, then `npm run release`, which inside GitHub Actions runs lint, build and `npm publish`
  with `NPM_CONFIG_PROVENANCE=true`. `npm publish` outside this path is blocked by the
  `prepublishOnly` guard of the template. An unscoped package is public by default, so
  `--access public` is not needed.

Secrets:

1. **Now**: the `NPM_TOKEN` repository secret (Settings › Secrets and variables › Actions), a
   granular npm token with read and write access, created on 2026-10-27 for 7 days. Publish before it
   expires, or create a new one.
2. **After the first publication**: on npmjs.com, package › Settings › Trusted Publisher › GitHub
   Actions, with owner `pocket-communication`, repository `n8n-nodes-biway-messenger`, workflow
   `publish.yml` and no environment. Then delete the `NPM_TOKEN` secret and revoke the token: the
   workflow falls back to OIDC by itself.

Releasing 0.1.0: `package.json` already says `0.1.0`, so the tag is placed by hand on `main` once the
phases are merged (`git tag 0.1.0 && git push origin 0.1.0`). `npm run release` on a workstation would
bump the version first. For the next versions, `npm run release` on `main` bumps the version, updates
the changelog, tags and pushes; the push of the tag publishes.

After publication:

1. `npx @n8n/scan-community-package n8n-nodes-biway-messenger`: checks the provenance, downloads the
   GitHub commit it points to, and lints both that source and the published tarball;
2. submission on the [n8n Creator Portal](https://creators.n8n.io/nodes).
